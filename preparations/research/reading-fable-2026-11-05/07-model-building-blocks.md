## The model stated back in my own words, to check I have it

A store's definition declares **atom kinds** (a content schema, some dimensions each with a scale, write rules, moves) and **templates** (ordered slots with cardinality, each for an atom kind or a template; relations among its slots; and the whole's own dimensions: aliased, derived, own). The store holds **instances**, each of one template, each with one identity and a history of names, filling slots with **atoms** or with other instances. Dimension values live on atoms and on instances. A dependency is not a separate edge object: it is the value of a reference-scaled dimension on an atom, pointing at other atoms. Writes happen only as **instance-isolated changesets**. A stable store is perturbed by one of those; more are staged; the **frontier** says what is not yet consistent; the **atomic changeset** is the whole set that restores consistency, and only that may reach the steady state. Files are manifestations.

## Where I think it is not yet right (mine; to put to Joseph)

**A. "Unit of fate" is not well-defined at atom grain, independent of the `##` question.** "Refuted, superseded or ratified" are three different things happening on three different dimensions: truth, content/version, decision. An atom with two dimensions can be refuted on one and stand on the other. Appendix A's own first doubt was this ("a definition is a coinage (decided) and also fits usage (evidenced)"). RC1's substitution law, as PLAN reports it, says one dimension never stands in for another. So the thing with "one current epistemic label" is a *value* (atom × dimension), not an atom. The atom is the content those values are about. That is Joseph's definition.

**B. Atoms should be leaves.** If anything with separately-standing parts is an instance of a (possibly tiny, possibly unnamed, possibly embedded) template, then open question 2 ("atoms in a 0..N slot, or atoms nested inside atoms?") has an answer for every case I have seen: never nested atoms. Lettered items (a)–(h′) = a 0..N slot of item atoms in a statement template. Claim Record = a 0..N slot of embedded claim-record instances. And when a check narrows half an atom, the response is a changeset that splits it, which is a template-level act (the slot becomes 0..N, or a sub-template appears), not a new kind of nesting. Grain is then *discovered by adjudication and recorded as a split*, which is how ASF's (a)–(h′) actually came to be checked separately.

**C. Slot-filling has three cases, not two:** an atom; an embedded instance (owned, path-addressed, no independent name, shares the parent's instance-isolated changeset); a reference to an independent instance (a chapter's segments; has its own name and its own changesets). The second/third distinction decides what "one instance" means for an instance-isolated changeset. A chapter edit that reorders segments is one instance-isolated changeset on the chapter and touches no segment. An edit to a claim-record entry is part of the segment's.

**D. "Required slot" vs things that are deliberately not there yet.** 9 `--GAP--` rows and 6 `missing` stage cells in vol 1; a sketch; a deriv whose claim record says "Instantiated: not applicable". If validity = required slots filled, a placeholder is invalid. The knowledge-graphs read (via PLAN A8) says "unknown value" and "no value" should be positive statements. So a slot needs at least: filled / declared-not-applicable / declared-owed. "Owed" goes on the frontier, or on a standing list if it is accepted.

**E. The model is silent on template change.** The 2026-05-30/31 gold lift was, in this vocabulary, a template change (add a six-sub-slot block to a slot) applied to 120 instances in two days. Adding a required slot to a template makes every instance invalid at once. PLAN calls this a system episode and has `v2 reinit` for the verisectorium-level case. The model needs to say that a template is versioned and that an instance is of a template *at a version*.

**F. The intake half is missing, and it is where "real practical flow" lives.** Source, chunk, crossing; local influx; write-back; the three extra crossing outcomes (mint, stays-as-record, joined-as-source). In this vocabulary I think: a local influx is a 0..N slot on a template whose write rule is append and whose contents are *excluded from the instance's version*; a chunk is an atom of a chunk kind whose one dimension is its crossing; "stays as record" is a changeset that moves the atom from the influx slot into a guard slot (same content, different slot, now part of the version). But "Fills exactly one slot of exactly one instance" plus "address is instance#slot" makes moving an atom between slots an identity question, which is the model's own open question 1. So open question 1 is not only about splitting segments; it is hit by every drain.

**G. Acts that are also content.** A review has an author, sources, and per-check fields; it can itself be wrong (fidelity) and its author calibrated. A finding is a claim with a target. A run has parameters and output. Are these instances (they have content and dimensions) or events (they are acts on atoms at versions)? The model has "two families of event" and does not place things that are both. The feedback's boundary test says both: the review is an instance; each check in it is an event on another atom whose basis includes the review.

**H. Instance-own dimensions have no content to attach to.** "Coherence, teachability, importance-for-X" are values on the instance with no atom. Fine at graduation level 0–2. At level 3 (PLAN A2) the value reifies into something with content. In this vocabulary that is: mint an instance of a "coherence review" template and alias the dimension to it. Worth saying, because it shows graduation is expressible without new machinery.

**I. Collisions to name before they bite:** template/instance (store level vs unit level, same project, two days apart); atom/atomic (three senses in §4); "kind" (atom kind now, template maybe later, and RC1's kind); "stations" (PLAN: rule firings; feedback: roles with queues); "group" (retired here, but §7's "canonical grouping … an ordered group whose instance carries a coherence claim" uses it immediately after retiring it).
